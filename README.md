# dsh-bench · 插件测评站（MVP）

**真装、真用，替你踩雷。好用就说好用，翻车就把证据摆出来。**

这是一个**插件测评站**的最小可用版本（MVP）：替用户把插件装一遍、用一遍，再老实写报告。
本仓是 DSH 生态的一员，与 `dsh-market`（插件市场）、`dsh-nexttavern`（配套工具）同族。

---

## 现在到哪一步了

> **目前只有方案和验证计划，还没有经过验证的正式成绩。**

正式能力榜要同时满足三件事：端到端验证通过、首个能力域的任务和统计规范正式冻结、上线验收清单（16 项）通过。
**不是日子到了就开榜。** 在那之前，本仓只发体验快测和标清范围的方法试验。
仓里带「示例」标签的数据是**演示生成链路用的样例**，不是正式成绩。

## 怎么跑

只用 **Python 标准库**，不需要装任何依赖，不需要联网。

```text
# 1) 判定算法边界回归（端到端验证计划 §7 那张表，逐行读数）
python -X utf8 scripts/verdict.py --demo

# 2) 直接判定一个区间
python -X utf8 scripts/verdict.py --interval 6 10 --json

# 3) 发布前检查（必要字段、公式、证据链接、隐私、复核；不通过即拒绝发布）
python -X utf8 scripts/validate_data.py
python -X utf8 scripts/validate_data.py --release     # 正式发布模式：只收「正式」、拒示例

# 4) 生成静态站（Markdown 内容 + data/*.json → dist/）
python -X utf8 scripts/build_site.py
python -X utf8 scripts/build_site.py --official-only  # 不含示例数据

# 5) 守卫（逐条断言 + 边界表）
python -X utf8 tests/test_verdict.py
python -X utf8 tests/test_validate_data.py

# 6) 变异自证：注入必失败 ⇒ 守卫必红并点名到具体断言（多红少红都算错）
python -X utf8 tests/mutate_selfcheck.py

# 7) 公开面检查：不得含本机绝对路径、凭据、内部代号、内部私有路径
python -X utf8 scripts/public_check.py
```

生成后的站点在 `dist/`，直接双击 `dist/index.html` 即可离线浏览（纯静态，无外链、无脚本）。

## 交付件

| 路径 | 说明 |
| --- | --- |
| `scripts/verdict.py` | **★核心可验证件**：五状态判定算法（真有用／帮倒忙／没啥差别／还说不准／没法测）＋启动候选门槛 `a=b=5`、精度半宽 ≤5 ＋ 组合规则 ＋ 成本口径 ＋ 样本层校验 |
| `scripts/validate_data.py` | 发布前检查器：Schema 校验 ＋ **语义复算**（半宽公式、状态复算、到期日、成本分母、复核独立性、证据链接、隐私）。fail-closed |
| `scripts/build_site.py` | 静态站生成器：**成绩、区间、标签从有效证据自动算出，不接受手填**；发现手填或不一致直接中止构建 |
| `scripts/public_check.py` | 公开面检查：提交前扫绝对路径／凭据／内部代号／内部私有路径 |
| `data/schema/*.json` | 版本化 schema：`report` / `plugin` / `evidence` / `ledger`，每个都带 `schema_version` |
| `data/plugins|reports|ledger|evidence|examples/` | 版本化 JSON 数据（`examples/` 是演示样例） |
| `site/templates/` + `site/static/` | 中文界面模板与样式（简洁、可读、手机友好、易读字号、清楚按钮） |
| `content/pages/*.md` | Markdown 内容页（首页、方法、各域、排期、更正） |
| `tests/test_verdict.py` | §7 边界表逐行 ＋ 组合规则，共 34 条断言 |
| `tests/test_validate_data.py` | 校验器正例通过、各类缺项各自被拒，共 17 条断言 |
| `tests/mutate_selfcheck.py` | 定点变异自证执行器（50 条变异） |

页面（方案 §16/§17 建议路径）：首页／插件页／报告页／各域榜／方法页／排期页／更正页／账本页。

## 硬约束（方案写死的，代码里也守着）

- **不给总分**；**能力／好不好用／花费与安全三张单分开**，第三张里钱与安全**也分栏**。
- **不用星级、不搞全能总榜**；不拿星数／热度当能力。
- **装不上就写装不上，不编分数凑数。** 安装失败 ⇒ 能力「没法测」＋ 安装环节「失败」两条分别记。
- **「没啥差别」不是绝对一样。**
- **「还说不准」「没法测」照常展示，但不进数字排名。**
- **档位决定能说什么**：体验快测**不测能力 Δ**，只出「能力试跑（观察结果，不进榜）」，
  禁用「通过」「合格」这类词；标准测评才出五状态；深度审计＝标准测评 ＋ 六类安全专项
  （能力结论同规，多出安全专项面，且**未测就写未测**）。
- **安全提醒单独显示**；能力结果**不能被偷偷改成零分或抹掉**。
- 成绩默认**只管 90 天**，到期退出推荐与排名；**改日期不算续期**。
- **不在网站机器上运行不可信插件**：本站只读版本化 JSON，不执行任何插件代码；实验环境与网站服务器分开。
- **未测就写「未测」**，不留空。
- 「实验无效」（判分器故障／环境崩）**≠**「证据不足」：前者作废重跑并留痕，后者是信息不够。

## 局限（老实说）

- 本仓是 **MVP**：只有管线、规则和演示数据，**没有任何一个真实插件的正式测评成绩**。
- 统计实现（配对比例差区间、bootstrap）在真源里要求「预先冻结并经过边界测试」；
  本 MVP 只实现了**判定规则层与门槛**，区间**由上游产出后传入**（生成器/校验器会复算校验，不自己造区间）。
- 风险等级、题库生命周期、付费抽验等治理条款在真源中已写死，本 MVP 只落地了**数据模型与页面位**，未实现运营流程。
- 实验环境隔离（不在网站机器上跑不可信插件）在本仓体现为**结构边界与文档约束**，未做真实部署。
